# 数据导入与导出

设置中的“数据与备份”提供 JSON 完整备份恢复与成绩 CSV 导出。原有 HTML 采集文件导入仍属于成绩采集，不是备份恢复。

## 备份范围

格式标识为 `zfjw-toolkit-backup`，整数版本为 `1`。文档包含导出时间、应用版本及以下数据。

| 数据 | 内容 |
| --- | --- |
| `profiles` | 档案 ID、名称、创建时间、规则包 |
| `snapshots` | 全部成绩快照，含 ID、档案引用、来源、时间与原始记录 |
| `terms` | 课表学期、起始周一、总周数、检查时间 |
| `versions` | 全部课表快照及课次原始字段 |
| `preferences` | 教学计划、成绩与计划修改、GPA 目标、课表功能开关 |

设置使用显式白名单，`null` 表示尚未设置。备份不包含登录状态、缓存、任意其他偏好项或恢复日志。以后新增持久化业务数据时，应同步更新格式、校验器与往返测试。

## 恢复语义

导入在任何写入前完成校验。缺失字段、未知版本、无效来源、重复 ID、悬空引用及非法课次会被拒绝。确认时再次检查本机数据是否仍与预览一致；如果有变化，需要重新预览。

合并按 ID 比较实体，内容相同则跳过。相同 ID 的任何字段不同都会阻止合并，包含默认档案的创建时间或课表学期的检查时间。设置中的非空内容与本机不同也视为冲突；不会自动选择较新的值。替换模式则完整采用备份，并清除备份中未设置的白名单设置。

合并历史后，现有“最新采集时间优先”的规则继续决定当前成绩和课表；浏览 CSV 历史选择页不会改变当前数据。本轮不提供成绩历史切换、删除或 CSV 导入。

## 一致性与中断恢复

数据库版本 3 新增 `backup_restore_journal`，保存恢复前后的白名单设置和提交标记。恢复先写日志，再在一个 SQLite 事务内替换业务表、写入设置、标记提交并清除日志。日志清除失败也会回滚事务，避免提交后清理失败却报告导入失败。

- 事务失败时，SQLite 自动回滚，协调器按日志恢复旧设置。
- 启动时，未提交日志恢复旧设置；已提交日志补齐新设置。
- 恢复完成后才清除日志，重复恢复保持幂等。
- 启动恢复失败时不开放业务页面；运行中补偿失败时停留在恢复页，保留重试入口。

文件选择和保存由 `DocumentGateway` 隔离，系统实现使用 `file_picker`。读取备份通过流限制为 64 MB。取消文件窗口不会报告成功；保存成功后才显示“文件已保存”。

## CSV

当前模式导出应用手动修改后的成绩，历史模式导出选定快照的原始成绩。列顺序固定，使用 UTF-8 BOM、CRLF 和双引号转义。可能被表格软件当作公式的文本会添加单引号前缀，因此 CSV 是分析用的有损导出。

## 验证

`test/features/backup/` 覆盖完整往返、重复合并、冲突与过期预览、设置写入故障、SQL 故障、启动恢复与重试、旧库迁移、CSV 字节及界面流程。界面测试使用正式主题，覆盖 390 和 1200 像素宽度及明暗主题。

Android 真机测试由用户负责。Windows 实际窗口检查记录在本地任务的 Comments 中。
